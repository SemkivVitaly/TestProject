Wi‑Fi мост ESP32‑S3 (MAVLink) — краткий отчёт

Для Word: откройте этот файл через «Файл → Открыть». Сравнение с DroneBridge/DroneBridge.

Цель. Связать полётный контроллер с Mission Planner, QGroundControl и аналогами по Wi‑Fi без USB: прозрачный обмен UART ↔ TCP/UDP. Веб и API работают только в локальной сети платы (интернет не нужен). Настройки Wi‑Fi, UART и протоколов сохраняются в NVS и не сбрасываются при отключении питания.

Как подключать GCS. Типично: TCP на порт 8880 или UDP 14550 (как у стандартных наземных станций). В режиме точки доступа веб открывается по адресу платы (например 192.168.2.1); в режиме клиента удобен доступ по mDNS (имя задаётся в конфиге, например esps3.local). До четырёх одновременных TCP‑клиентов.

Главное для отдела

  • Диагностика канала и железа: RSSI в STA и в AP (в AP — усреднение по подключённым станциям, а не бессмысленный «ноль»); температура кристалла ESP32; по MAVLink — heartbeat, время с последнего heartbeat, счётчики пакетов, процент потерь, байты через мост; видимость TCP/UDP‑клиентов.
  • Логи под испытания и приёмку: единый текст (/api/log/file) — идентификатор устройства, статус связи с автопилотом, RSSI, t°, статистика пакетов, счётчики по типам MAVLink, hex‑образцы последних кадров RX/TX, хвост событий и лог ESP32. Дополнительно — JSON по пакетам и отдельный лог платы. Всё отдаётся по HTTP; выгрузку можно сохранить в файл из браузера и приложить к протоколу.
  • Веб‑функции: Bridge UI (метрики + форма настроек + добавление/сброс UDP‑клиента), главная с быстрыми ссылками, страница параметров SERVO (запрос/установка по MAVLink), JSON API для скриптов на стенде.
